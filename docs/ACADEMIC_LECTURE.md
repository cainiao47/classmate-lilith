# 学术讲座整理稿

在“整理成稿”的“成稿形式”中选择“学术讲座整理稿”。新任务默认使用此模式，历史任务保留原有模式和结果。

## 成稿要求

- 采用总标题、简短整理说明、主题章节和必要的小标题；程序统一编排章节与小节编号。
- 用完整自然段展开论述，调整碎句、口语反复、语序和有唯一依据的指代，保持可连续阅读的正式表达。
- 保留实质观点、具体例证、反例、个人经历、不同意见、数字、引文、限定条件和判断强度；不生成提纲式摘要，不补充外部知识。
- 允许保留必要的第一人称。不识别说话人，不根据语气、姓名出现或上下文猜测身份，不自动添加角色标签。原文明示的自我介绍、姓名与身份信息可以保留。
- 【待确认】及其存疑内容原样保留。整理不等于外部事实核验，仍需人工核对录音、引文和事实。

## 工作流程

1. 将全部校订原文分成有编号的原文块，分批建立主题章节、要点与保留信息。每个原文块必须按顺序恰好归入一个章节，避免遗漏和重复；超长原文不截去尾部。
2. 依主题章节改写。过长章节分为有界的连续部分，每部分带有目录、所属章节和前文衔接信息。
3. 每部分直接对照对应原文，核查遗漏、无依据新增、判断强度变化和文体问题。发现问题后修订一次并再次核查；仍未通过则暂停该段，保留此前已通过的部分，用户可继续整理。
4. 统一组装总标题、说明、章节标题和小节编号。长讲座同样逐段核查，不因全文长度而跳过核对。

结构方案、已完成分段和模型用量保存在任务历史中。暂停后继续会复用有效方案；改变原文、背景、术语或标题会重新生成对应方案。核对属于模型辅助编辑，不能保证发现所有语义遗漏或新增内容。

此模式会增加结构规划和逐段核查请求，必要时还会增加修订及复核请求，耗时和费用高于普通书面化。界面显示实际返回的累计模型用量。

## 导出

- Markdown：保留标题层级、重点加粗、整理说明和列表，已有总标题不会重复添加。可直接放入 Obsidian 仓库。
- Word：将 Markdown 中的标题、加粗、说明和列表转成相应的文档呈现，不显示原始 Markdown 标记。
- TXT：保留文字内容和列表顺序，去除 Markdown 标题、引用及加粗标记。

## 验证与验收

自动测试覆盖章节原文归属、超长输入完整性、存疑内容保护、核查修订、断点恢复、流中断识别、两种文字服务的请求格式及文档导出。服务调用测试使用本机模拟服务，不消耗真实 API 额度。

实际文体验收应使用含理论、具体案例、限定语和存疑内容的真实校订稿：核对是否遗漏信息或增加判断、是否保持讲者立场，以及是否形成连贯段落。没有可用的文字模型 API 凭据时，只能完成模拟服务与程序流程验证，不能宣称已完成真实模型的文体验收。
