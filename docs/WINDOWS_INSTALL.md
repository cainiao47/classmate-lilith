# Windows 安装与更新

## 当前发布状态

Windows 正式版为 [v0.22.2](https://github.com/cainiao47/classmate-lilith/releases/tag/v0.22.2)（2026-10-21），提供重新构建的 EXE 安装器、便携包、校验文件及签名更新清单，已合并 v0.21.1 源码及本轮新增功能。macOS 保持 v0.21.1。此前误编号的本地 v0.18.0 包不应用于覆盖 v0.21.1，也不能只改文件名当作新版。版本对应关系见 [版本核对记录](VERSION_AUDIT.md)。

## 安装版

下载 `Classmate-Lilith-Setup-版本号.exe`，按照向导安装。默认安装到当前用户的 `%LOCALAPPDATA%\Programs\Classmate Lilith`，无需管理员权限。可以创建开始菜单和桌面快捷方式。

v0.22.2 起需要 .NET Framework 4.7.2 或更新版本，以启用 WinForms 的 PerMonitorV2 高清缩放；安装器会检查依赖，缺少时明确提示，不会自动改动系统运行时。原生窗口会按屏幕实际 DPI 渲染，移动到不同缩放的显示器时自动适配，不通过固定页面缩放模拟 DPI。无需降低 Windows 的正常缩放比例。

`Classmate Lilith.exe.config` 与程序必须一起保留；更新助手的 `.config` 也会随助手一起复制。若曾手动设置 Windows“兼容性”的 DPI 缩放覆盖，建议先取消该覆盖再测试新版。网页页面缩放仍由用户自行调整，修复不会重置已有缩放偏好。

安装版将设置、API 凭据、术语库、任务、人工版本和录音保存在系统“文档”中的 `Classmate Lilith\data`，日志保存在同级的 `logs`，更新缓存和备份保存在 `updates`。本机默认路径为 `C:\Users\Li\Documents\Classmate Lilith\data`。程序采用 Windows 的真实“文档”位置，不硬编码 C 盘；文档被重定向到 D 盘或 OneDrive 时也会跟随。

如果系统“文档”由云盘同步，上述数据可能随之同步，包含录音和 API 配置，请确认同步设置。变更系统“文档”位置前先退出程序，并确保数据随文件夹一并迁移。程序本体仍安装在上面的程序目录；覆盖安装只替换程序文件。

交互卸载会显示完整的数据路径，提供“卸载并保留数据（推荐）”“卸载并删除数据”“取消卸载”三个选项。默认保留；选择删除还需第二次确认，且确认默认选择“不删除”。删除范围是系统“文档”下的 `Classmate Lilith`，包括设置、API 配置、工程、版本、录音、窗口缓存、日志和更新备份，不影响旧便携版目录、上版旧位置的数据副本或另行制作的备份。删除不可撤销。

静默卸载始终保留数据，不支持用命令行参数删除数据。自定义环境变量指向的其他数据目录不在自动删除范围内，须自行备份管理。升级覆盖安装不会触发清理用户数据。

当前安装器及启动器尚未使用公开受信任的 Windows 代码签名证书。Windows 可能显示未知发布者提示，部分设备的安全策略可能阻止运行。应用的更新包签名用于核验更新来源，与 Windows 代码签名是两回事。

## 从旧便携版导入

1. 在旧版中保存任务，通过系统托盘“退出并停止服务”。保留完整旧版文件夹。
2. 首次运行安装器，在“保留旧版数据”页选择旧版目录，而不是其中的 `data` 子目录；不需要导入时留空。
3. 安装器复制并逐文件校验旧数据，将任务元数据中属于旧 `data` 目录的录音路径指向新目录，凭据文件保持原有格式。
4. 导入成功后启动并检查历史、录音与设置。旧文件夹不会被删除，可在确认后自行归档。

v0.21.1 的 WebView2 窗口缓存及 `.launcher-token` 不跨版本导入，由新版重新创建；工程、人工版本、录音、术语和 API 配置均保留。完整原缓存仍留在旧目录及用户单独制作的完整备份中。

升级 v0.22.0 时，若检测到 `%LOCALAPPDATA%\Classmate Lilith\data`，而“文档”下还没有数据，安装器会预选旧位置，复制并校验其中的数据、调整录音路径。旧位置不删除，便于回退；旧日志和更新备份也保留在旧位置，不会重复复制。

“文档”中已有安装版数据时，向导会跳过导入，继续使用它，不覆盖合并其他位置的数据。复制中断、空间不足或元数据损坏时不会删除旧数据，也不会自动启动空白工作台；错误记录位于“文档”下 `Classmate Lilith\migration-error.txt`。确认错误已处理且新目标目录没有既有数据后，可重新运行安装器导入。

## 应用内更新

工作台右上角有“检查更新”。程序启动后自动检查正式版，单次运行内缓存六小时；按钮可手动重新检查。网络失败不影响当前版本使用。

发现新版后可下载更新包。应用先验证内置公钥对应的 Ed25519 发布签名，再校验下载文件大小和 SHA-256。用户确认“保存并安装更新”后，程序保存当前任务，检查其他页面是否有未保存修改、实时录音或运行中的任务；有则停止安装，提示先处理。

准备安装时暂停新的后台写入和实时连接，备份程序及设置、术语库、任务和人工版本，录音原地保留。独立更新助手等待本地服务与托盘程序退出，再运行安装器，最后重启并检查新版服务。安装或启动失败时尝试恢复先前程序文件；用户元数据备份保留以供手动恢复，不自动用旧数据覆盖新数据。

更新缓存、程序回退副本和升级日志位于系统“文档”下 `Classmate Lilith\updates`。备份包含个人数据，请勿公开分享。录音文件不会为了每次升级再复制一份。备份和已下载更新可在确认新版稳定、退出程序后手工清理。

只有安装版支持应用内安装。便携版继续将数据放在自身的 `data` 和 `logs` 中，可检查更新并下载；转为安装版时按上面的导入步骤操作。

## 发布维护

- 版本号以 `package.json` 为准，正式更新只接受三段数字版本，测试版不进入自动更新通道。
- 更新签名公钥：`distribution/windows-update-public.pem`。私钥不随安装包分发，不提交 Git。
- 本机发布私钥首次生成在忽略目录 `release/keys/windows-update-private.pem`，必须单独备份，丢失后不能直接替换现有公钥来更新已安装的版本。
- GitHub 自动构建需要配置同一私钥的仓库 Secret：`WINDOWS_UPDATE_PRIVATE_KEY`。不要配置模型 API Key 或个人 GitHub Token 到客户端。
- 新的 `windows-release.yml` 只构建和发布 Windows。旧双平台发布流程保留为手动触发，本轮不构建或更新 macOS 包。
- 发布资产必须包括 EXE、校验文件和签名清单 `windows-update.json`；在 GitHub 正式发布后，客户端才能发现该版本。

## 本机构建与验证

```powershell
node distribution/sign-windows-update.mjs --init-key
.\distribution\build-windows-base.ps1 -RuntimeSeed C:\path\to\trusted-runtime
.\distribution\build-windows-installer.ps1 -PackageRoot .\dist\Classmate-Lilith-Windows-x64 -InnoCompiler C:\path\to\ISCC.exe
.\distribution\test-windows-installer.ps1 -Installer .\dist\Classmate-Lilith-Setup-版本号.exe
```

安装演练会在仓库 `temp` 下创建隔离的程序与数据目录，测试首次安装、保存设置与历史、覆盖重装、数据哈希、卸载保留数据。若发现已有正式安装的卸载登记则中止，避免影响用户安装。演练不会创建快捷方式、连接真实模型服务或使用现有用户数据。

`distribution/test-windows-uninstall.ps1` 另行编译仅用于测试的微型安装器，在固定隔离目录验证取消卸载、保留数据、删除数据和目录链接不越界删除。测试钩子只存在于该临时测试包，正式安装包不包含测试选择参数；正式静默卸载始终保留数据。
